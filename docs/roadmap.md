# Request Control roadmap

This roadmap contains work intentionally kept out of the first modernization release so that each engine change can be validated independently.

## 1.16.0 — modernization foundation

Release scope:

- current Firefox request engine remains the compatibility reference;
- local URL analyzer and disabled-by-default rule suggestions;
- managed/community rule provenance and safe subscription reconciliation;
- SHA-256 verification for community rule files;
- additive rule groups and collapsible groups inside existing action categories;
- modern options/popup styling and dark mode;
- Node 22 and current lint/test/build toolchain;
- current GitHub Actions, Dependabot and automated release/tagging workflow;
- complete upstream issue/PR triage.

## Next: SPA/history-state adapter

Upstream references: #168, #178, related #118.

- Handle `webNavigation.onHistoryStateUpdated` through a dedicated navigation adapter.
- Reuse shared matching/transformation semantics where request context exists.
- Do not invent HTTP method, request origin or other data unavailable on SPA navigation events.
- Define behavior for Filter, Redirect, Secure, Whitelist and Block explicitly.
- Prevent redirect loops and unnecessary history entries.
- Add regression cases for YouTube-style `pushState` navigation and tracking-parameter cleanup.

## Next: Chromium Manifest V3 / declarativeNetRequest compiler

- Keep the existing Firefox engine as the golden reference during migration.
- Compile representable rules to DNR static/dynamic rules.
- Capability-report rules that cannot be represented exactly instead of silently approximating them.
- Cover query transforms, regex redirects, blocking, upgrades, request types and rule priority with golden tests.
- Produce separate browser manifests from one source model.
- Only switch Chromium to MV3 when the supported capability set and limitations are explicit.

## Next: Rule Assistant phase 2

- Opt-in, short-lived local trace of current-tab navigation/request URLs.
- Cluster similar URL samples and identify stable vs changing query parameters.
- Show why a candidate parameter looks removable or necessary.
- Generate a draft rule and run it against captured examples before saving.
- Never execute destructive probe requests automatically.

## Later: optional LLM assistant

- Deterministic analyzer remains primary.
- LLM input is minimized structured data by default, not raw browsing history/page contents.
- Provider is explicit opt-in.
- LLM output is declarative rule data only; never executable JavaScript.
- Strict schema validation, static safety checks and local tests before a rule can be saved.
- Generated rules remain disabled until user review unless a future, separately reviewed trust policy explicitly allows otherwise.

## Community catalog expansion

- Add more current rules only with example URLs and compatibility tests.
- Port useful ideas from upstream PR #167 selectively after current-site validation.
- Do not adopt upstream PR #124 wholesale; later upstream experience showed broad `sid` removal can break legitimate services.
- Add catalog schema validation, duplicate UUID detection, hashes and versioning to all rule sets.
- Add contribution templates and automated rule regression tests.
- Treat ratings/reactions as secondary metadata, never as a safety decision.

## Catalog contribution UX

- Export a single rule or rule group in contribution-ready format.
- Generate a GitHub issue/PR template payload without requiring a personal access token in the extension.
- Include test URLs, expected result, category/group and rule provenance.
- Consider GitHub Discussions/reactions for community feedback after the repository settings support it.

## Release quality gates

Every release must satisfy:

1. clean dependency install from the committed lockfile;
2. unit tests;
3. source/JSON/web-extension lint;
4. extension build;
5. built ZIP lint;
6. green aggregate `checker` on the release PR;
7. manifest version and changelog aligned;
8. release ZIP generated by CI, not from a developer working tree.
